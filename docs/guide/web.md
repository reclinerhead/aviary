### The web app (`web/`)

A Next.js App Router app: TypeScript, Tailwind 4, pnpm. It was born as the Merle Control Center, the vision daemon's dashboard (epic #1), and #628 retired that dashboard; the directory and the unit kept the MCC's names (`mcc/`, `mcc-dashboard`) until the cutover renamed them (#666). All three boxes have run this layout since their cutovers (orchid 2026-10-28, the stations 2026-10-30). The Aviary lives in it, with the weather station view as its fourth masthead tab since #652 (each has its own spoke); `/weather` is a permanent redirect to `/aviary/weather`, and `/` redirects to `/aviary` (`app/page.tsx`, a server-side 307), which is where a stale bookmark lands at home. On a station the app never answers `/`: `Servers/Caddyfile.station` gives `/` and `/porch/*` to the porch (below), the twins' paths to the twins, `/quarry` to `:3020` and `/conservatory` to `:3010` (#684; `handle`, not `handle_path`, since each twin is built for its prefix), and everything else to `:3000`. The twins' routes are written into the file rather than imported so a missing twin can never take the Aviary down.

**The porch (`porch/`, #696)** is the station's launcher: one page at `/` with a photo tile each for the Aviary, the Quarry and the Conservatory, so the one bookmark a household has (`aviary.toddtech.llc/<station>`, which redirects to `/`) reaches all three. The house has it as well, at `https://aviary.lan/` (#700). It is not part of the Next app.

- **Static, and served by Caddy itself** from `porch/` in the checkout: `index.html`, `porch.css`, `porch.js`, five self-hosted font files and three default photos. No build, no unit, no port, so it stays up when any of the three apps is down, and it arrives on a box with the pull. Hand-written CSS is the deliberate exception to the Tailwind rule here, because there is nothing to build it. The look is the Quarry's design language (`reclinerhead/quarry` `design/DESIGN.md`), light and sized for older eyes.
- **It claims exactly `/` and `/porch/*`.** The route's `root` is the checkout, where `earl.db` and `weather.db` also sit, so the path matcher is the whole exposure: nothing outside `porch/` is reachable through it.
- **Whose house it is comes from a file, never from code.** Caddy rewrites `/porch/station.json` to `porch/stations/<hostname>.json` (`{system.hostname}`), and that file holds the station's display name and the name the greeting uses. A hostname with no file is a 404 there, and the page says "Home" with an unnamed greeting. A new station is one new JSON file.
- **An app can live at another name** (#700). At the house the porch is `https://aviary.lan/` (orchid's Caddy, in `home-automation`), and the Quarry and the Conservatory are not under that origin: each sits at the root of its own name. A station file's optional `apps` object gives the origin, `{ "quarry": "https://quarry.lan" }`, and that tile then links there. Its cover request does not move: the page still asks its own origin, and orchid's Caddy passes `/quarry/api/cover` and `/conservatory/api/cover` on to the twins, so nothing is cross-origin and the twins need no change. The `src` that comes back is a path at the root of the twin's own name, so the page reads it against that origin. A value that is not a bare origin is ignored. A file with no `apps` is a station, where all three share the box's one origin.
- **A tile shows one photo, not two** (#702). With scripts on, each tile holds its photo and caption back, over its dark well, until its cover is settled: loaded, or known not to be coming. So the default is a fallback and never a first frame. A tile stops waiting after 1.5 seconds and shows its default; a cover that arrives later still swaps in. With scripts off, or if `porch.js` fails to load, the defaults show at once.
- **Each tile's photo is the app's to choose.** On load the page asks `/aviary/cover`, `/quarry/api/cover` and `/conservatory/api/cover` for `{ src, caption, credit }`, preloads the image, and only then swaps it in. Anything else (a missing route, a non-200, four seconds without an answer, `src: null`, a `src` that is not a path, an image that fails) leaves the default photo, silently. The defaults and their licences are in `porch/CREDITS.md`.
- **Nothing leaves the box on load.** The fonts are self-hosted and the only outside link is the footer's.
- **Caddy reads the files as the `caddy` user**, which must be able to traverse `/home/todd` (the runbook's `setfacl` line). Without it every porch request is a 403 with nothing in any log. `Caddyfile.station` is synced by hand, so a change to the route reaches a box only when Todd copies and reloads it.

- **Production runs on orchid** as `aviary-web.service` (`next start` from `~/aviary/web`, port 3000) after #371 Phase 3 and deploys via `Servers/deploy-web.sh` — the script enforces pull → install → build → restart, because `next start` serves the compiled `.next/`, not source: pull + restart re-serves the old code, and building after the restart rewrites `.next/` under the live server. A `fast-stop.conf` drop-in sets `TimeoutStopSec=5` (Next's graceful shutdown waits on browser keep-alive connections, up to systemd's 90s default — the app is stateless with nothing worth waiting for). Product doors: `aviary.lan` / `weather.lan` via orchid Caddy (`Servers/Caddyfile-orchid`); the `mcc.lan` door retired with the dashboard (#628), its Pi-hole record with it. Orchid's Caddy compresses compressible responses at the choke point (`encode zstd gzip`, issue #494) — Next gzips page HTML but route-handler JSON bypasses its compression, and the Aviary roster (~206 KB raw, ~64 KB gzipped, refetched every mount + every 60 s) was the dominant recurring payload on remote sessions; images, clips, and websockets pass through untouched. Ops detail: `toddtech-infrastructure/servers/Orchid.md` § Phase 3. Autodeploy rebuilds the app only when a merge touched `web/` (`MERLE_DEPLOY_MCC=1`), install → build → restart, and a failed build never restarts it: old code keeps serving, which is the whole safety net for a build failure that CI cannot see (the `web` job runs Vitest, `tsc --noEmit` and ESLint, not `next build` — so `pnpm build` runs locally before any PR that touches this app).
- **The browser dials the broker directly** (`lib/bus.ts`): an HTTP proxy can't carry WebSockets, so the pages connect to Mosquitto through the house front door's `wss://pearl.lan/bus` route (pearl is the house's DNS box; its Caddy proxies to orchid's broker) (#399 — Caddy carries the upgrade to :9001; `NEXT_PUBLIC_MERLE_MQTT_WS` in `web/.env.local`, a **build-time** value that is never copied onto a station: the stations' plain-HTTP porches dial `ws://<host>:9001`, `busUrl()`'s fallback). The audio contract (`audio/events`, `audio/status`, `audio/sources` and their parsers, Vitest-covered) and the retained weather topics are the whole of what the browser subscribes to; `voiceColor()` (the art-directed cast accents, #89/#92) survives for Willard's on-air stamp.
- **Gotcha — import the browser build of mqtt.js.** `WeatherStationView.tsx` and `Aviary.tsx` import `mqtt/dist/mqtt.esm`, not the default `mqtt`. The default entry is mqtt.js's **Node** build (Buffer + node streams); Turbopack bundles it for the browser, but it can't serialize packets there, so the CONNECT never sends and the client dies with `connack timeout` (~30s) — the connection opens but never completes the MQTT handshake. The `dist/mqtt.esm` build is self-contained for browsers. Types are borrowed for that subpath in `lib/mqtt.browser.d.ts`. An `error` handler on the client is mandatory: mqtt.js is an EventEmitter, and an unhandled `error` throws in the browser and wedges its own reconnect loop.
- **Gotcha — a JSX attribute string must stay on one line** (issue #657). A double-quoted attribute that spans lines (`info="… at the⏎   station …"`) compiles differently for the server bundle and the browser bundle: the server collapsed the line breaks and indentation to single spaces, the browser kept them. The server's HTML and the browser's first render then disagree, and React throws `#418` and re-renders the whole page client-side on **every production load**, while `next dev` never reports it. The weather view's UV note did exactly that from #63 until #657, and it was only noticed because the console stayed noisy after #652. `components/jsx-attributes.test.ts` now fails CI on any attribute string that crosses a line under `components/` or `app/`; long text goes on one line, or into a `{"…"}` expression. When chasing a `#418`, count the errors per load: the browser pane's console log carries over between page loads, so a message on the current page may belong to the previous one.
- **Gotcha — the SQLite driver is `node:sqlite`, the stdlib module** (issue #105's open question, resolved by checking rather than assuming; the `/weather/history` route first, every `/aviary/*` read route since). It needs **no dependency and no native build on the box**, which is what settles it against `better-sqlite3` (proven and synchronous, but a native module wanting a build toolchain). The catch is that it has been experimental and flag-gated: unflagged from Node **23.4**, and it stops emitting an `ExperimentalWarning` somewhere in 24.x (orchid's 24.18 is quiet; a 24.14 desk still warns on import — harmless, and the reason a stray warning in a build log isn't a bug). **If a box's Node is ever downgraded below 23.4, these routes are what break.** Two consequences already visible in the repo: `@types/node` had to go from `^20` to `^24` (the types ship with the runtime, and `next build` type-checks the routes), and the routes are untested in CI — the `web` job pins Node 22, where the import would need a flag. That's tolerable only because nothing in Vitest imports a route; their pure halves (`parseRange`, the roster shaping) live in `lib/` and are covered there. The stores live in the checkout root on every box, `~/aviary/earl.db` and `~/aviary/weather.db` (#666 moved them out of the squirrel checkout), and `aviary-web` carries both paths absolute. The databases are opened **read-only, per request** rather than cached in a module: the app doesn't own the files, on a fresh box a route can serve traffic before the writer has created them, and a cached handle would pin that day-one miss until the next deploy — a local SQLite open is microseconds.
- **Design language: "Ranger Station, Night Watch"** — pine-black panels with topographic-contour background, Fraunces display type + Sometype Mono telemetry, and three species accent colors that *were* the vision stack's literal box colors (squirrel `#FF7031`, chipmunk `#FF3838`, turkey `#CFD231`), kept as the palette's heritage inks since #628 (the voice colors, the hover ink) because the rule below grew around them. Tokens live as CSS variables in `app/globals.css`. The two muted inks were raised in #222 — the original `--ink-faint` measured 3.0:1 against `--panel-2` and was unreadable on real hardware at the 9–10px mono sizes it mostly renders at; both now clear WCAG AA worst-case (faint 4.9:1, dim 7.6:1), same sage hue, hierarchy intact. Re-tune by measuring against both panel surfaces, never by eye.
- **`--wing` `#9db35c` is the palette's second non-species accent** (issue #185), and it extends `--rain`'s rule rather than bending it: species colors were the vision stack's literal box colors and mean *"this species"*, while this names a **module** — the Aviary, whose visit chart counts any bird. Per-species meaning is carried by the page itself (a profile chart is already about one bird), so the bars need module identity, not taxonomy. Not invented for the chart: it's the blaze the launchpad's Aviary placard has worn since the tile went live, so the module reads the same from the porch to its own instruments (the narrators' voice-color idiom). **Validated, not eyeballed**: chroma 0.13 clears the 0.10 floor, contrast against `--panel` clears 3:1, and CVD separation from `--led` — the nearest green, and the one it must never be confused with, since green means *live* — is deutan ΔE 13.2 against a target of 12. `--led` never appears as a bar, so the two never share a mark. (The dataviz validator's *lightness-band* check fails this palette wholesale, `--rain` and `--squirrel` included: that band is tuned to its own reference palette, while this one did its own lightness reasoning in #113 and its inks sit where pine-black needs them.)
- **The palette has two kinds of accent, and the distinction is the rule** (issue #113). The three species colors mean *"this species"* and were the vision stack's literal box colors — never pick them for decoration. **`--sky` `#7a9eb8` (issue #92)** is Willard's voice ink — a muted slate-sky for the name stamp and entry rail on his on-air segment, deliberately *not* `--rain` so precip bars and the weather man never share a mark. **`--rain` `#6bb6e5` is the first accent that isn't a species**: it names something the station *measures* rather than something the model *detects*, which is the line that keeps the species rule intact. It also gives `--led` its one job back — green means **live** (presence lamps, on-air stamps, the falling-now dot), and it had been moonlighting as rain since #56. It was **chosen by the validator, not by eye**, and the finding is worth keeping: *any* blue light enough to match `--led` (OKLCH L 0.829) or `--turkey` (0.835) falls under the 0.10 chroma floor and reads **gray** — blue's gamut peaks darker than green and yellow, so "match the palette's brightness" is a trap. `#6bb6e5` (L 0.746, C 0.12) is the brightest blue that still reads blue, and it lands between `--squirrel` (0.711) and `--led` — inside the palette's own range. Its CVD separation from every other ink is ≥ 34 ΔE against a target of 12; the palette's genuinely tight pair remains the pre-existing chipmunk↔squirrel (ΔE 10.1 deutan), which is why `SPECIES_ORDER` keeps orange and red from ever touching. The notice inks (`--notice`, `--fact`, epic #447 / #422) follow the same measured discipline; their reasoning sits beside the tokens in `globals.css`.
- **Tests**: pure parsing and shaping live in `lib/` (`aviary.ts`, `weather.ts`, `bus.ts`) with Vitest coverage (`pnpm test`); components are visual and untested per the testing policy. Known UI gotcha encoded in comments: no `Date.now()` in render (SSR/client hydration mismatch).
- **Lint is the React Compiler's gate** (`reactCompiler: true`; CI runs `tsc --noEmit` and `pnpm lint` in both Next apps since #679). The `react-hooks/*` rules are the compiler's own checks: a component that reads a ref or the clock in render, or a callback that names itself in its own initializer, is either skipped by the compiler without a word or compiled with a stale value. So those errors get fixed, not suppressed. Read the clock in an effect or take it as a prop; keep per-row facts (the ticker's and the archive's `live` glow flag) on the row, not in a ref; mirror into state anything render needs from a ref. Two suppressions are sanctioned, each `eslint-disable-next-line` with its reason: `react-hooks/set-state-in-effect` on the **post-mount pattern** (client-only values — storage reads, the viewer's clock and local midnight — land in a mount effect so server and client first paint match) and on the archive's page-one reset, and `@next/next/no-img-element` on portraits (the portrait route owns thumbs and versioned caching, #495). Never suppress `exhaustive-deps` or `rules-of-hooks`: the compiler treats those suppressions as a reason to skip the function. Lint can't see every skip. Compiler 1.0 also skips any function containing a `try`/`finally`, or a loop, conditional, `??` or `?.` inside a `try`/`catch`, and any manual `useCallback`/`useMemo` whose deps disagree with what it infers (it counts state setters, so list them). Keep a `try` to the bare call that can throw, or use a promise `.catch` (#680). Every component in `web/` compiles today.

### The listener (`listener/` — Earl, the ears of the house)

Epic #133 Phase 1 (issue #172): a pearl-resident daemon (`listener/earl.py`) that pulls raw audio from the yard's microphones, runs Cornell's **BirdNET** (the `birdnet` 0.2.x package, `"tf"` backend — 0.2.x dropped tflite) on every 3-second window at 48 kHz, and publishes accepted detections to `audio/events`. Earl is deliberately **domain-agnostic**: he reports what he heard (species, confidence, source, clip path); consumers decide what it means. The first consumer is `listener/sightings.py` — the frame_archiver mold — which turns `audio/events` into the bird record: an append-only `sightings` table plus the **life list** (one row per species ever heard, with its first-heard moment). Phase 0's proof and measurements live in [#133's results comment](https://github.com/reclinerhead/project-squirrel/issues/133); the numbers that shaped this design: inference ~1.2 s per 3 s window per stream via a warm `predict_session()` (real time on one core, so the Coral is a scale play, not a prerequisite), and false positives without region filtering clustered at 0.25–0.61 while true locals scored 0.89–0.92.

- **The YAMNet classifier** (issue #174, Phase 2a): every window meets **YAMNet** (521 AudioSet classes, TF Hub SavedModel, CPU — ~56–80 ms per 3 s window on pearl) before BirdNET. `gate.route()` returns one of three verdicts from a curated, name-verified class map (`earl.py` warns at startup about entries the loaded model doesn't know — the typo'd-constant lesson): **speech** kills the window outright, checked first and at a deliberately *lower* floor (`SPEECH_FLOOR` 0.1, **not configurable**), so the epic's invariant is enforced by a model with real speech classes, with BirdNET's human check remaining as the second layer; **notable** (dog, glass, siren, thunder, engine, cricket…) emits a `kind:"sound"` event — coarse class, no species fields, rms, its own `VisitTracker` (class names and species names are different vocabularies), and **no clip since #327** — *and the window still goes to BirdNET*, because a barking dog doesn't mean no bird is singing; **listen** is everything else. **Only speech withholds a window from BirdNET** — this is the module's central contract, and `MERLE_EARL_GATE_FLOOR` (default 0.3) governs *sound events only*.
  - **Why it is not a gate, in the architectural sense.** It shipped as one on 2026-07-18 — only bird-routed windows reached BirdNET — and ate **17 of 25 confirmed yard detections** in an afternoon (a 0.97 pheasant, a 0.88 waxwing, a 0.86 nighthawk), because (a) it was desk-validated on a close-mic'd clip scoring `Bird=0.52` while real distant yard birds score a *median of 0.189*, several with no bird class in the top-7 at all, and (b) AudioSet is a **hierarchy**: on faint audio the parent classes fire hardest (`Animal=0.505` where `Bird=0.463`), and the map had been built from plausible-sounding names rather than measured behaviour. `Animal`/`Wild animals` accordingly moved into `BIRD_CLASSES` (reporting only now) and out of `NOTABLE_CLASSES`. The deeper error was accepting a veto at all: gating BirdNET was justified solely by CPU savings, and pearl idles at load 0.00 running two ears — the premise was dead before the code shipped. `test_listener_gate.py` now carries the real YAMNet scores of those confirmed birds as regression fixtures.
  - Per-worker counters log every 100 windows (`gate stats: … listen, speech-killed, notable, ungated; gate N ms avg`). A classifier that can't load runs Earl **ungated** (Phase 1 posture) loudly. The YAMNet call sits behind one function (`load_yamnet()`'s `classify`) — **the 2b seam**, which now carries two arms (#300): `MERLE_YAMNET_TFLITE=<path to yamnet.tflite>` selects a **LiteRT arm** for the no-AVX stations (epic #212 — full TF can't import there, and an ungated station box would break the epic's speech invariant), unset is the hub arm untouched; the Coral phase adds a third the same way and nothing upstream moves. The LiteRT arm frames the 3 s window into the tflite variant's fixed 0.975 s input at half-frame hop and **means per-class scores over frames** — the hub arm's `scores.mean(axis=0)` reproduced one level up, so the gate's tuned floors keep their meaning; the 521 display names ride inside the `.tflite` itself (zip member `yamnet_label_list.txt`, same vocabulary as the hub CSV), and the startup `unknown_gate_classes` check runs against them identically. Measured on birdhouse: 9.7 ms/frame, ~50 ms per 3 s window — the hub arm's class. Either arm failing to load still runs Earl ungated and loud. Audio reaches it at 16 kHz via mean-of-3 decimation; BirdNET always sees full-rate. `sightings.py` needed zero changes — its ignore-unknown-kinds guard (#172) is the two-tier schema's compatibility mechanism, working as designed. It needed **one** change eventually (#324): the guard was silent about *persisting* but loud about *seeing*, announcing every sound event as a `dropped malformed message`, so a summer yard of crickets filed hundreds of incident reports a night about a mechanism working perfectly. `is_other_kind()` now separates the two verdicts `parse_event`'s `None` used to conflate — a well-formed event of any non-`detection` kind (including kinds invented after this code shipped, which is the forward-compatibility guarantee) passes silently, while unparseable bytes and a `detection` missing its required fields keep the loud line they earn.
- **The gate rules** (`listener/gate.py`, pure — every rule under `test_listener_gate.py`): (1) **speech is never an event** — a window whose top label is Human-anything produces no event and no clip, by construction, not by setting (epic principle 1: Earl classifies, he never records conversations); lower-ranked human labels are dropped individually. (2) **The region mask (D4, mandatory)**: BirdNET's geo model, fed `MERLE_LATLON` + the BirdNET week (48-week year, 4/month — `week_of()`), yields the locally-plausible species set; everything else is discarded. Recomputed when the week ticks; a geo-model failure runs **unmasked and loud**, never silently eventless. (3) **The threshold** (`MERLE_EARL_THRESHOLD`, default 0.65 — between Phase 0's false-positive ceiling and true-local floor), which wind **raises but never lowers**: above 15 mph the bar becomes 0.75 and survivors carry `wind_suspect: true`. Wind arrives from the retained `weather/current` on Earl's own MQTT connection (the narrator's staleness rule: a report older than 30 min degrades to calm-day rules — the Ecowitt earns its keep again).
- **Process model — shaped by the fork trap.** `birdnet`'s predict calls fork worker children, and forking while any thread holds a lock (paho's network thread qualifies) deadlocks the child **silently** — Phase 0 lost a debugging cycle to this. So the parent (`Earl`) owns all MQTT and never loads birdnet; each source runs in its own **spawned** worker process (fresh interpreter, no inherited locks, `daemon=False` — daemonic processes can't have children, and birdnet's session needs children) that stays single-threaded around its predict session and reads its capture pipe with bare `os.read` (no buffered-reader lock). Workers report over a spawn-context queue; wind rides a shared `Value` the other way. A dead capture restarts with backoff (3/10/30/60 s) forever; a dead worker is respawned by the parent; neither kills Earl.
  - **Stalls, not just exits** (issue #201): that restart loop only ever fired on a capture that *ended*, and the field's real failure is a capture that **hangs while still running** — the Amcrest unplugged and moved mid-session sends no TCP reset, so the socket stays `ESTAB` and ffmpeg blocks on it forever; merle powered down to recharge half-opens the ssh, whose kernel keepalive is ~2 hours away. Either way the source dies **silently** — no log line, no state change, the service healthy-looking — which is precisely how one went unnoticed for an hour on 2026-07-19. Three layers, and the first two exist to turn a stall into an exit so there is exactly **one** path back online rather than a second parallel recovery: (1) ffmpeg's `-timeout` (the *rtsp demuxer's* socket-I/O bar, in **microseconds** — **not** `-rw_timeout`, which that demuxer does not carry; measured on pearl's ffmpeg 8.0.1 against a socket that accepts and never speaks, it exits in ~9 s where the unflagged run was still waiting at 20 s); (2) `ServerAliveInterval=5`/`ServerAliveCountMax=3` on the rover's ssh; (3) `read_exact`'s **`select` timeout**, the source-agnostic backstop, which gives the read a third answer — `STALLED`, a sentinel object distinct from EOF's `None` because the caller's whole branch is an `is` check. It is `select` on the fd and **not a watchdog thread** for the same reason the worker is single-threaded at all: a thread here is the fork trap. The bar is **bytes, not windows** — the clock restarts on every chunk, so only a source that has gone completely quiet for `STALL_TIMEOUT_S` (15 s, five missed windows) is called stalled, and one dribbling slower than the timeout still keeps its window. A stall kills the capture and falls into the same backoff, logging `capture stalled` rather than `capture ended` so the journal distinguishes the two. Net field behavior, which is the actual acceptance bar: **a device can be gone for hours and its source resumes within ~60 s of coming back, unattended** — the backoff cap, since a window that arrives resets `backoff` to 0.
- **Sources come from the project feed registry** (`feeds.yml`, repo root — issue #270): every feed flagged `earl: true` becomes a worker, and `source_commands()` dispatches on the feed's **kind**, never its name — no source name appears in code, so adding a camera or retiring a mic is a registry edit. Kinds: `rtsp` — ffmpeg audio-only pull of the feed's `url` (`-allowed_media_types audio`: the 48 kHz AAC track alone, none of the 4K video's bandwidth; camera-side audio must be enabled in each cam's web UI — the Save button is load-bearing), normally Frigate's credential-free go2rtc restream (#247), today `house-rear` and `house-front`; `command` — the feed's `cmd` verbatim, today `rover` (`arecord` on merle piped over ssh, the USB camera's own mic `plughw:0,0` — Phase 0 D5: the JMTek dongle is silent; requires pearl→merle ssh keys, a deploy step, and the cmd's `ServerAlive*` flags are #201's layer 2, regression-guarded by `test_feeds.py` now that they're data). All sources produce s16le/48 kHz/mono on stdout; the `-timeout` stall bar (#201) rides every rtsp pull. **The `earl:` flag is the CPU dial**: flip a camera to `false` and redeploy to drop it — the two-BirdNET-workers load question answers itself in config, not code. The `rover` feed sits at `earl: false` since #375 (declaration and keepalives intact): the mic is single-open and belongs to Field Mode ([the fieldmode spoke](fieldmode.md)), and the tailnet ended the era when distance freed it — MagicDNS resolves `merle` to its tailnet address, so an Earl pull follows the rover onto a park hotspot and starves the field session. Flip it back for a parked-at-home era; automatic arbitration is the #375 follow-up. **Break-glass for a Frigate that's down**: point `MERLE_FEEDS` at a local, uncommitted registry whose rtsp feed carries the direct camera URL (credentials and all — `rtsp_argv` redacts every log line); the old `MERLE_EARL_SOURCES`/`MERLE_RTSP_*`/`MERLE_EARL_ROVER_CMD` env family is retired. A feed's name doubles as its published source label and clip directory, so **renaming a feed is a data migration** (the #270 runbook in `Servers/Pearl.md` — `amcrest` → `house-rear` was the worked example). Per-source health is **state** on the retained `audio/sources` JSON (`starting`/`online`/`silent`/`offline` + last-window ts, republished on change — `silent` means ~1 min of rms-nothing, a mic that died upstream of the codec); `audio/status` itself stays a **raw** `online`/`offline` string with Last Will, the `weather/status` contract verbatim. (The epic sketched per-source detail *in* the status payload; the house convention — status topics are raw strings consumers render verbatim — won, and the detail moved to its own topic.)
- **Visits — the species-level debounce** (issue #175, `gate.VisitTracker`, pure): day one measured **3.2× event redundancy** (one singing cardinal = 25 events/rows/clips) and a disk burn 10× the deploy estimate — the `SpeciesPresence` failure mode, one sense over. A *visit* opens on a detection of species S with no S-detection in the preceding `VISIT_GAP_S` (60 s) and stays open while they keep arriving; only the **opening** detection publishes (liveness: consumers hear the arrival in seconds, nothing waits for the bird to stop). Later windows are suppressed, except that a window beating the visit's best confidence **rewrites the visit's clip in place** — the published clip path never dangles, and a lifer's `first_clip` ends up holding the bird's best moment. Visit close is a lazy sweep on the worker's own thread (no timers — the fork-trap rule) that logs the stats (`visit closed: Northern Cardinal, 25 windows, 96s, best 0.90`); the journal is where a visit's true best lives, since the published event carried the opening window's confidence (append-only store, no UPDATE path — accepted trade-off). Visits deliberately survive capture restarts (a reconnect inside the gap continues the visit); species interleave independently; sources stay share-nothing.
- **Clips (D1: files + paths)**: a per-source ring of raw windows; a **bird** visit-opening (or best-upgrading) window is written as prev+event+next (~9 s of context) under `MERLE_EARL_CLIPS/<source>/<epoch>-<species>.wav` (allowlist-scrubbed names — the frame_archiver rule), and the event carries the relative path. **Sound visits write nothing (#327)**: `sightings.py` never persists `kind:"sound"`, so such a clip is unreachable by any route, table, or query the moment the live ticker moves on — measured on birdhouse's first outdoor evening, orphaned cricket WAVs were **43% of the station's clip tree**, and #325 had begun enhancing them too. The event still carries class, confidence, and rms, so the ticker, the gate stats, and the future training loop (#278) keep every observation; only the bytes stop. Clips can return if sound events ever gain a persistent consumer — ideally on a narrower allowlist than every notable class. **One clip per visit** (#175), not per window. A failed write is a clip-less event, never a dead worker. `publish_bytes()` stays the frames' idiom — clips are 10–100× frame size and both ends live on pearl.
- **The bird record** (`listener/sightings.py`, own unit): `sightings` is append-only with an id key (two species can share a window's ts) and, since #175, an `rms REAL` column — the window's raw signal level, persisted because **confidence is model certainty, not loudness**, and Phase 5's "heard strongest at the east cam" ranking needs the real number (day one: rover louder in 7 of 9 same-window pairs). `connect()` adds the column to a pre-#175 file idempotently (the repeatable-pass rule — an upgrade is a restart, not a migration script; old rows honestly NULL). `life_list` uses `INSERT OR IGNORE` so **first-heard is enforced by the store** — replays and restarts can never move a `first_ts`. Epoch-seconds timestamps (the audio namespace is epoch end to end, the weather reasoning). `MERLE_EARL_DB` (default `earl.db` under `WorkingDirectory`) is the **third irreplaceable file** the stack owns, after `weather.db` and `music.db`'s ratings: a first-heard date is a moment no API sells back. **It is therefore the one store that syncs on every commit** (`synchronous=FULL`, issue #322) and **checkpoints at connect** — a deliberate divergence from `weather_archive`'s `NORMAL`, argued in `connect()`'s own docstring: under NORMAL a WAL commit isn't fsynced, durability waits for a checkpoint ~1000 pages away, and a yard writing a handful of tiny rows a day can go *days* between checkpoints. Birdhouse measured the consequence on its first cold power-off (epic #212): schema intact, **zero rows**, the whole day-one record gone — plus a ten-minute window where the pending WAL-index recovery had the writer and every reader disagreeing about the store's contents until a full-scan read forced the rebuild and discarded the frames written against the stale index. Folding at connect bounds both: every unit restart lands the tail in the main file and performs the recovery at startup rather than mid-write. The checkpoint is best-effort (no busy timeout — a live reader returns busy instead of delaying startup). A sighting missed while the consumer restarts is a bus moment nobody archived — but the clip Earl wrote is still on disk, so a future backfill pass over `clips/` can heal the record (the enrichment-pass ethos).
- **Locations — the bird record is per-place** (issue #232, Field Mode epic #230 Phase 1): a `locations` table (`id`, `name`, `lat`, `lon`, `created_ts`) makes Home just one place among possibly many, so a park session can never bleed into the home roster. **Location 1 is Home**, seeded at first upgrade from `MERLE_LATLON` — set on the `earl-sightings` unit now (Servers/Pearl.md); unlike `earl.py`, sightings treats it as *optional* (a consumer that does no geo work shouldn't die over a missing locator) and seeds a `(0,0)` placeholder that self-heals the moment real coords arrive, so deploy ordering doesn't matter. `sightings.location_id` is `NOT NULL DEFAULT 1`, so **every pre-#232 row backfills to Home for free** — no row rewrite. **`life_list` is re-keyed to `(species_sci, location_id)`**: first-heard is now a per-place fact, so a robin at the park is a park lifer even though Home has heard hundreds; the old single-PK table is rebuilt-and-copied in `_upgrade()` (SQLite can't `ALTER` a primary key), every existing row preserved as Home with `first_ts`/`first_source`/`first_clip` untouched. `audio/events` grows an **optional** `location_id` (absent → Home): live Earl publishes exactly as before — zero home behavior change — and the Phase 3 import pass is the first publisher that stamps a park's id. Fresh-DB and upgraded-old-DB land on byte-identical schema (a `PRAGMA table_info` fingerprint test asserts it). `sightings.py` gained a lean `from listener import gate` (pure, `re`-only) to reuse `parse_latlon` — inside the `test_import_boundary.py` poison, since `gate` is already on the safe side of it.
- **Clip retention** (#175) lives in `sightings.py`, not `earl.py` — deliberate: the store knows which clips are irreplaceable, so the store prunes. Hourly (first pass at startup, so a long-down consumer heals immediately), on the main thread beside paho's loop, with its own short-lived read connection. **Two arms, in order: the age horizon, then the disk budget** (#330). Files older than `MERLE_EARL_CLIPS_KEEP_DAYS` (default 90) are removed, **except every path in `life_list.first_clip`, exempt forever** — a lifer's first recording is part of the permanent record — and **except the permanent shelves**: `species/` (portraits, #184) and `quarantine/` (a species removal's evidence, #281 — the negatives-in-waiting for epic #278's false-positive loop), which share the clips dir but are not rolling windows. Since #232 that exemption is **per-location by construction**: one `first_clip` per `(species, location)` row means the first recording of each species *at each place* is spared, no extra logic. Selection is pure (`prune_selection()`, injected clock + listing + exempt set — the `frame_archiver` precedent). Pruned rows keep their `clip` path: a missing file is an honest gap, the Field Journal's pruned-thumbnail convention. **Enhanced siblings (#190) share their original's fate exactly** — a doomed clip takes its `-enh.wav` with it, and a lifer's exempt clip keeps its sibling. Judging a sibling on its own age would be wrong in both directions: it is always the newer file (a later pass wrote it), so it would outlive the evidence it enhances, and an exempt lifer's sibling would age out from under a permanent clip. An orphaned sibling — original already gone — has nothing to inherit from and ages out on its own. The suffix is duplicated as a two-line constant here rather than imported: `clip_enhance` needs numpy and this unit runs from the lean repo venv, which `test_import_boundary.py` enforces.
  - **The disk budget** (`MERLE_EARL_CLIPS_CAP_GB`, issue #330 — unset means no cap and the pre-#330 behavior exactly). **Age cannot protect a volume it does not measure**, and pearl proved it: measured 2026-07-28 at ~668 clips/day × 831 KB, doubled by #325's automatic siblings — roughly **1 GB/day** onto a 47 GB LV shared with the music cache, which fills the disk in about a month and never reaches day 90. Every clip on the box was younger than 30 days, so the age sweep had **never once fired in production**. `budget_selection()` is the second pure arm (the `prune_selection` precedent, one measurement over): evict **oldest first** until the tree fits, with three rules that hold under any pressure — a lifer's first recording is *never* evicted (if the sacred set alone exceeds the cap, the pass takes everything it may and the caller says so **out loud**, because deleting first-heard evidence to satisfy a disk number trades the one irreplaceable thing for the cheapest thing); the permanent shelves — `species/` portraits and `quarantine/` removal evidence (#281) — are never evicted but **are counted**, since measuring only the evictable half would make the cap a lie the moment the permanent half grew (and evicting a hand-labeled negative to satisfy a disk number would silently undo the operator's work); and an enhanced sibling is evicted as one unit with its original, freeing both files' bytes. Budget evictions log **separately** from age prunes and always — an age prune is policy working, a budget prune means the yard is outrunning the disk and somebody should know (the no-silent-caps rule, on the one tree that holds evidence). `list_clips()` now returns `(relpath, mtime, size)` from a single `stat()` serving both arms.
- **Vocal fill** (`listener/clip_vocal_fill.py`, issue #442): pure bird-band song fraction for each visit clip, persisted as `sightings.vocal_fill` (nullable REAL). Used by the Aviary's `bestClips` so a fuller song can beat a single high-confidence warble among near-top confidence visits. **Not automatic in the enrichment loop in v1** — operators backfill once per box after deploy: `python -m listener.clip_vocal_fill` (with `--dry-run` / `--limit` / `--force` / `--refresh RELPATH`). Idempotent: rows with a non-null fill are skipped unless forced. Score is band-limited (~1.5–8 kHz) frame activity above a pre-roll noise floor — broadband `rms` is deliberately not reused. Unscored stores keep confidence-only ranking. pytest: `test_listener_clip_vocal_fill.py`.
- **Clip enhancement** (`listener/clip_enhance.py`, issue #190): the pass that makes a faint bird *audible*. A large share of real clips are birds buried under a plane, road noise, wind, or HVAC — BirdNET finds them anyway, but the clip is the only evidence a human can independently evaluate, and a high confidence on a barely-audible signal is exactly the profile of a plausible false positive. Being unable to hear the clip means being unable to check the model. Three steps, and **the order is the design**: (1) **band-limit** — songbird song lives ~2–8 kHz while the interferers are overwhelmingly sub-1 kHz, so a rolloff below 1.5 kHz (raised-cosine, not a brick wall, which rings) removes most of the noise and almost none of the bird; (2) **spectral subtraction using the clip's own pre-roll as the noise profile** — the key move, and nearly free, because `write_clip()` already stores prev+event+next, making the leading 3 s *this exact acoustic scene without the bird in it*, a perfectly matched per-clip estimate; subtraction uses a proportional spectral floor, since subtracting to zero is what produces musical noise; (3) **normalize, last** — normalizing first would normalize *the plane* and leave the bird just as faint in relative terms. Measured on a synthetic 9 s clip (0.9-amplitude rumble, 0.012 warble): event-window level vs pre-roll goes from 0.97 (indistinguishable) to the bird alone at full scale. **numpy only** — `numpy.fft` covers both the FFT-domain band and the STFT, and scipy would fight the lean-venv posture for no gain. The STFT pads both edges by a full window overlap: without it the first samples sit under a single Hann taper whose overlap-add divisor approaches zero, which turns the clip's opening into a 300× spike *the moment the spectrum is modified* — it round-trips fine unmodified, so the trap only springs once the pass does its job. **Never in place**: a later `best` verdict rewrites clips, so the pass writes a sibling `<stem>-enh.wav` and the original is never modified or deleted. Idempotence falls out of mtime — a sibling newer than its original is skipped, and a rewritten clip is newer than its sibling and gets re-enhanced for free, so file existence is the source of truth and no schema changed. Worklist-driven with `--refresh`/`--limit`/`--dry-run` (the `species_profile` shape; a future per-clip re-enhance button calls what `--refresh` calls). **Since #325 the enrichment loop runs this pass automatically on both roles** (its third pass, bounded per tick, same per-clip functions as the CLI) — the manual-only posture ended when pearl's ENH toggle turned out to have been silently falling back to raw for weeks of un-passed clips, and when stations arrived whose passive-mic clips are born ~20 dB quieter than camera-AGC audio (measured, #325: the same Blue Jay at −34 dBFS on birdhouse and −12.6 on pearl) — the normalize step is what makes those audible at all. The hand-run CLI remains for forcing and inspecting.
- **Deployment**: House Earl lives on **orchid** after #371 Phase 6 (`Servers/Orchid.md`); pearl units stay disabled. Listener runs from its **own Python 3.11 venv** (`~/earl-venv` — BirdNET's TensorFlow has no wheels for the repo venv's Python; built with `uv`) as `earl-listener`; `sightings` needs only paho and runs from the **repo venv** as `earl-sightings`; **`earl-enrichment` also uses the repo venv and needs `numpy` there for the clip pass** (#325) — BirdNET's numpy in `~/earl-venv` does not count. A lean repo venv built with only mqtt/yaml leaves the loop up while every tick logs `clip pass FAILED (No module named 'numpy')` and the Aviary never gets `-enh` siblings (measured on pearl after #325 and orchid after #437). Stations that install full `requirements.txt` already have numpy. Unset, the kwarg is omitted entirely. Stations also set `MERLE_YAMNET_TFLITE` to a local `yamnet.tflite` (the classification variant, ~4.1 MB — fetching it is a bootstrap step in `Servers/Birdhouse.md`, #302); the gate then runs its LiteRT arm (#300, see the classifier section above). A station's whole configuration arrives via one env file (`station.env.example` documents the contract) and its Earl listens to the committed `feeds.station.yml` — the local `window-mic` arecord feed, pointed at by `MERLE_FEEDS`, with `SupplementaryGroups=audio` on the unit (service sessions get no console ACL grant — the 2026-07-26 lesson). House clips: orchid `~/media-cache/earl` (or `/srv/…`); stations use their media-cache LV. Setup and unit files: `Servers/Orchid.md` (house), `Servers/Pearl.md` (historical house recipes), `Servers/Birdhouse.md` (stations). `requirements.txt` is untouched for birdnet — it lives only in Earl's venv, and `test_import_boundary.py` asserts the whole `listener` package imports clean under poison (earl.py's heavy imports are lazy, inside the worker functions), so the lean sightings unit can't die reaching for TensorFlow.

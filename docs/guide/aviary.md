# The Aviary

> Spoke of the [Merle Technical Guide](../../TechnicalGuide.md) — read the hub first for the machine roster, quick start, and cross-cutting conventions.
>
> **Covers:** Earl's GUI — `/aviary` + `components/Aviary.tsx` in `mcc/`, its read routes over `earl.db`, the visits chart, field notes, and the `listener/` enrichment passes behind them (`species_profile.py`, `species_analysis.py`, `enrichment_loop.py`)
>
> **On stations (epic #212):** the same loop runs **without field notes** (#312) — Wikipedia profiles and the clip pass, but no LLM prose, because `MERLE_OLLAMA` is absent from the station env and `run_analysis_pass()` short-circuits on an empty candidate list. No code arm, no profile flag: the kill switch that already existed *is* the station mode. The hosted-model notes are the epic's post-birthday addition.
>
> **The loop's third pass is clip enhancement** (#325, both roles): every original clip gets its `-enh.wav` sibling within a tick, bounded per tick with deferred counts logged. Automatic because pearl's ENH toggle silently played raw for weeks of un-passed clips, and station clips are born ~20 dB quieter than camera-AGC audio.
> **Runs on:** orchid (MCC production + house `earl-enrichment` after #371 Phase 6); **front door** `https://aviary.lan/`

- **Product URL vs process.** The Aviary is a **peer product at the front door** (`aviary.lan` / `aviary` — Pi-hole → pearl, Caddy reverse_proxy to the same `mcc-dashboard` `:3000` as `mcc.lan`, with `/` → `/aviary`). Paths stay `/aviary`, `/clips`, `/_next` under that host. This is **Option A** identity split: not a second Next app. Homestead's tile opens `https://aviary.lan/`. `mcc.lan/aviary` still works so nothing forces a cross-origin break inside the control-center process.
- **The Aviary** (epic #182 Phase 1, issue #183, `/aviary` + `components/Aviary.tsx`): the Earl Birdwatch GUI — every life-list species as a tile with its visit count, a live ticker of arrivals with inline clip playback, and a per-species profile page (`/aviary/[species]`, keyed by **scientific name** — the stable identifier BirdNET emits; common names are display). Read-only end to end — until #216 carved the one deliberate exception, species removal (its own bullet below); the reader routes still never write `earl.db`, and the listener needed zero changes. The launchpad's Earl tile went live pointing here (name "Aviary", presence lamp on `audio/status`).
  - **Read routes over `earl.db`** — the `/weather/history` shape verbatim: `/aviary/roster` (life list joined with per-species visit tallies + today's count) and `/aviary/recent` (newest sightings first; optional `species` filter — one sci name or a comma-separated list, exact-match parameterized — an optional **inclusive** `before` ts cursor for the archive's pages (#211), and an optional **inclusive** `since` ts floor for the profile's last-24h Recent Visits (#276, `parseSince`-clamped to a recent window so a bogus value can't scan the whole store); limit clamped at both ends of the wire). `/aviary/recent` orders by `ts DESC, id DESC`, not bare insertion order: the cursor paginates on ts, and cursor and order must ride the same axis — bare `id DESC` matched ts order only by the coincidence of sequential insertion (measured breaking on a store with out-of-order timestamps); id still breaks same-second ties, keeping two species sharing a window stable. `node:sqlite`, read-only per-request open, quiet `{...: []}` for unset env / missing file / missing tables, **no default path** (`MERLE_EARL_DB` must be absolute in the `mcc-dashboard` unit — the two-WorkingDirectories lesson, third occurrence). `/aviary/recent`'s body is **byte-shaped like `audio/events` payloads** (`kind:"detection"`), so `audioEventFrom()` in `lib/bus.ts` parses hydration and the live bus with one function and the two can't drift.
  - **Visit counts are grouped at query time, never rewritten in the store**: `tallyVisits()`/`collapseVisits()` in `lib/aviary.ts` mirror `gate.VisitTracker` exactly (60s gap against the *last* detection, strictly-greater opens a new visit), so the pre-#175 per-window day (25 rows per singing cardinal) counts as one visit while post-#175 rows pass through unchanged. The same walk records each species' **`last_ts`**, the opening moment of its most recent visit (#549) — a continuation row never moves it — and the dashboard's live-event merge advances it by the same opening rule. Grouping ignores source on purpose — two mics hearing one cardinal is one bird visiting. "Today" buckets a visit by its **opening** detection and the boundary is the **client's local midnight**, passed as `?today=` and clamped server-side to ±2 days (the server can't know the viewer's timezone; a typo can't relabel the archive).
  - **The portrait route** (`/aviary/portrait/<species_sci>`, issue #184; cache policy #432/#433, two sizes + versioned tier #495) serves the enrichment shelf under `MERLE_EARL_CLIPS/species/`. The URL carries the scientific name; `speciesImageName()` re-derives the scrubbed filename (same regex as the pass). Quiet 404 while a lifer is still undressed. **Two sizes since #495**: `?size=thumb` asks for the pass's tile-sized `-thumb.jpg` sibling (`speciesThumbName()` — the suffix is applied to the already-scrubbed name, so the traversal guard's verdict is unchanged by construction), and **a missing sibling falls back to the full file in the route** rather than via a client 404-retry — existence is still the only state consulted (the #331 honesty), but an un-backfilled species costs one request instead of two, and the version token below is what tells caches when the sibling lands. The small surfaces (grid tiles, ticker + archive thumbs, New Arrivals cards, the events solo band, the notice strip) ask for the thumb; the profile hero backdrop and magazine figure keep the full file — the one surface that renders it at documented width. **Caching is two-tier.** Version-less URLs keep #432's policy: `public, max-age=86400, stale-while-revalidate=604800` + an **ETag** from file mtime+size and **304** on `If-None-Match` — because the same path can be rewritten in place, which is exactly the objection #433 recorded against `immutable`. #495 answers that objection with a **version, not a policy change**: the roster route stats both shelf files per species and ships an opaque `image_v` (`portraitVersion()` — full mtime+size dot thumb mtime+size, with a missing thumb versioned as `0-0` so the backfill *landing* is itself a URL change); `portraitUrl(sci, {thumb, v})` puts it in the query, and a versioned ask answers `public, max-age=31536000, immutable` for either size. A replaced portrait — enrichment refresh, owner drop — changes the stat facts, the roster (`no-store`, refetched every mount and every 60 s) re-derives `v`, and every consumer walks to the new URL on its next fetch; nothing ever revalidates an immutable answer because nothing needs to. Rows without an `image_v` (no `MERLE_EARL_CLIPS` in the route's env, shelf file gone) emit version-less URLs and simply ride the older tier. Missing portraits stay uncached 404 so a pending tile can appear after the pass.
  - **The clips route** (`/clips/[...path]` from `MERLE_EARL_CLIPS`) is `/frames/[id]` one sense over: `clipRelPath()` mirrors `gate.clip_relpath`'s allowlist (exactly `<source>/<name>.wav`, `[A-Za-z0-9_-]` only, no dots outside the extension), quiet 404 for missing/unsafe, and a pruned clip renders the "faded" stamp in the reserved player slot, never a broken control. **Served `no-store`, not `immutable`** — decided during #183: best-clip upgrades rewrite a visit's clip **in place** (#175), so an immutable-cached replay during an open visit would pin the opening take and hide the bird's best moment, the one thing best-clip exists to keep; clips are ~9 s LAN-local WAVs fetched by hand, so honesty costs nothing. **It speaks RFC 7233 byte ranges (#377), and that is not an optimization** — WebKit probes every `<audio>` source with `Range: bytes=0-1` and treats a 200-with-full-body answer as a *failed* load, so from #183 until #377 every clip was unplayable on iPhone/iPad while desktop engines shrugged the 200 off. Worse, the player then read the double failure correctly and stamped the clip **faded** — the pruned-file verdict, reached from sound evidence that was never true. A single range gets `206` + `Content-Range`, an unaskable one `416`, everything else the full `200`; all three carry `Accept-Ranges` and a real `Content-Length` (the old chunked response never told the engine the media's size at all). Parsing is `parseRange()` in `lib/aviary.ts` with the edge cases under test — suffix ranges, ends past EOF, empty files, multi-range asks (ignored, answered whole, which the spec permits). The accepted race: a best-clip rewrite between two ranges of one playback can mix takes, the same window the chunked stream always had, and `If-Range`/ETag is the escalation if it ever audibly bites.
  - **Live mechanics are the Field Journal's**: hydrate over HTTP, then merge live `audio/events` over mqtt.js (browser build) with stable content-derived keys (`audioEventKey`: ts|source|kind|species — two species in one window differ, a republish dedupes), prepend-on-arrival with the filed-flash reserved for genuinely live rows (hydrated rows are already-read — the broadcast view's `openedWith` lesson). A live detection **is** a visit opening (#175 publishes only the opening window), so counts increment per event by the same rule the query-time grouping applies. `kind:"sound"` events (#174) render as quieter species-less rows and vanish on reload — bus-only by design, `sightings.py` doesn't persist them (accepted asymmetry, #182). The masthead wears an Earl presence lamp off retained `audio/status`, so the ticker's empty state can tell "listening, quiet yard" from "bus down" — and beneath it a single stamp line of per-source health off retained `audio/sources` (`house-front [online], house-rear [silent], …`, sorted by name): process presence on top, which mics are actually feeding underneath. Wire states are `starting`/`online`/`silent`/`offline`; an `online` source whose `last_window_ts` is inside 60 s is labelled **capturing** (warm `--turkey`) so a recent event reads as activity without inventing a fifth wire state. Colors: capturing → turkey, online → led, offline → inkfaint, silent/starting → inkdim. Empty roster stays quiet (no fake line).
  - **New Arrivals** (issue #224): the rail's middle panel, between the ticker that mentions a lifer once and the visitors rail that treats it like a regular. Species first heard inside the window (24 hours by default — tightened from 48 in #226 — a week on an EnhanceToggle-idiom `24h`/`7d` nameplate) render as **featured cards**: full-rail-width portrait (the 4:3 top-crop tile idiom; a not-yet-dressed lifer wears the pending glyph in the same reserved frame until #217's loop gets to it), display-type name, first-heard moment, lifer number, and a play slot for the first-contact recording — #220's affordance promoted to where the excitement is. **Zero new backend**: a pure filter (`newArrivals`) over the roster the grid already maintains, so a live lifer surfaces the moment the bus announces it (the ticker-prepend precedent — appearing is the panel's purpose; existing cards never reorder, and the window's `now` advances only on the reconciliation poll's once-a-minute tick (#352, revising the original mount-time freeze) — so a card ages out when its window truly passes rather than never, which on a days-open kiosk tab kept the `24h` nameplate honest, while still never vanishing mid-read on an ordinary render). The empty state holds the panel's footprint with the honest sentence for the active window — most days, and deliberately so: the quiet frame is what makes a card landing feel like an event.
  - **The recordings row is the bird's repertoire** (#551 Phase 2, reshaping the row below): **three play slots of one geometry** — `best recording` (still `bestClips`, below), then `second call` and `third call` from the listener pass's `species_showcase` table (`docs/guide/earl.md` § The species showcase: the fullest clips that sound *different* from every earlier slot, BirdNET-embedding distance ≥ 0.30 plus the neighbour rule). The roster route reads the table with **one separate query joined to `sightings` for the take's date** (the `RULES_SQL` shape — a whole optional table asked about on its own, never a cascade rung; a store the pass has never run on answers with none) and `showcaseBySpecies()` (pure, Vitest) shapes it onto `RosterEntry.showcase`. **Slot 1 renders from `best_clip`, not from the table**, so the #447 new-best announcement keeps observing exactly what it observed; the table's slot 1 is the same clip by the fixture-pinned rule and exists for retention's sake. All three slots always render — an unfilled call is the reserved dot with a dash and a title saying the showcase fills in as the bird shows more of its repertoire — so a species growing a second call reflows nothing (house rule #1). One `RecordingEntry` serves all three (three callers, so they cannot drift). **First contact's play button is gone**: first heard is a date and lives on the **facts row** beneath (first heard · visits · today · detection — the same stamps, one line of their own), and the visit count carries thousands separators (a house species past 1,000 visits is the common case; `3003` read as a year). The #333/#442 ranking below is unchanged.
  - **The two recordings** (issue #333, repositioned into the hero's metadata row by #339; superseded on the page by the row above, the ranking still stands). Earl has curated a best-of-visit clip since #175 — a window beating its visit's best **rewrites that visit's clip in place** — and until #333 the page played only `first_clip`. Measured on pearl: for **43 of 73 species the best-confidence visit is not the first** (American Goldfinch spans 0.65–0.98 across 636 visits), so "first contact" was frequently a mediocre take while a near-perfect one sat on disk reachable by nothing. **The metadata row leads with the best recording** as its first and loudest entry — the larger `PlaySlot` (`big`, the same component at `h-11 w-16` so the two variants can't drift) beside the confidence in the display face and its date — then first heard, visits, today. **First contact has no row of its own**: its regular-size slot sits inline beside the first-heard entry, because first contact *is* `first_ts` — the standalone row #333 carried spent a full line restating the date directly above it to hold one button. **Ranked by stored confidence plus vocal fill (#442)** — confidence alone crowned a single high-confidence warble over a fuller song on the same life list. `vocal_fill` is the bird-band song fraction of the visit clip (0..1, listener pass `python -m listener.clip_vocal_fill`, persisted on `sightings.vocal_fill`); among visits near the top confidence (`cMax − 0.05` or ≥ 0.90), the higher fill wins. Unscored stores (every fill NULL) keep pure confidence ranking so an un-backfilled box does not break. Confidence is still the visit's **opening** window — the true peak lives only in the journal (#175's append-only trade-off) — so this remains "the best recorded *visit*" with a second axis for *how much song is in the clip*; the file a listener hears is best-of-visit either way. A clip-less row can never win — crowning it would pair a confident number with silence. `bestClips()` is pure and Vitest-covered, and rides the walk `tallyVisits` already makes over every sighting: **no second query, no second scan**. **One geometry in every state** (house rule #1): the slots always render — the reserved no-clip dot while the entry is in flight or for a pre-clip-era lifer, the faded stamp for a pruned file — so the fetch landing reflows nothing. When best *is* first contact (30 of 73 species — the common case, not an edge) the two slots share one clip path and light together: one file, honestly presented twice; the "still unbeaten" reserved row died with the block.
  - **The audio toggle tells the truth** (issue #331). Enhanced playback asks for the `-enh` sibling and silently falls back to raw on a 404 — that retry *is* the existence check, since the pass keeps no state and file existence is the source of truth. What was missing is that the fallback **threw the answer away**, so the nameplate kept reading ENH while raw audio played: for weeks that made a completely idle enhancement pipeline look like a working feature (pearl had siblings for 3.3% of its clips and no one could hear the difference, because there wasn't one). The player now remembers in a `rawOnly` set, and two things say so: the slot wears a hairline `r` notch inside the geometry it already reserved, and the ENH nameplate drops from the squirrel accent to faint ink while what's sounding is raw. **Not an error state** — since #325 enhances on a 5–15 minute tick, a fresh clip is legitimately raw for a few minutes, which is a recurring condition deserving honest chrome rather than an alarm.
  - **The archive hero** (issue #260; **readout strip in #418**, retiring the four-tile / dual-tile KPI band from #413/#415): a single compact panel between the masthead and the two columns — status-line density, not a scoreboard. **Two lines:** (1) *today* (distinct species with `today > 0` + `detectionsToday` = sum of per-species `today` tallies), *week* (distinct species with `week > 0` + `detectionsWeek` = sum of per-species `week` tallies — same species/detections pair as today), *record* (species count + whole-record visit total); (2) *pace* (mean visits/week and /month over days-on-air) and a quiet *listening since* + inclusive days stamp. Group labels (*today* / *week* / *record* / *pace*) match the figures (`text-[15px]` / `sm:text-base`); unit words (*species* / *detections* / *week* / *month*, …) sit one step down (`text-[13px]` / `sm:text-sm`) so they stay readable without matching figure weight; middots between paired facts; no per-metric card borders and no reserved empty sub/foot rows. The standings band on the species profile keeps its own `StandingTile` idiom (#220) — deliberately not shared. **Everything derives from the roster state the page already maintains** (`archiveStats()` in `lib/aviary.ts`, Vitest-covered): zero fetches of its own, live detections tick the figures in place, and "this week"/"today" mean *distinct species with `week`/`today` > 0* — the roster's own windows, no third boundary definition, and deliberately not new-lifers (that's New Arrivals' job). Pace is `visits * 7 / days` and `visits * 30 / days` over that same inclusive span — not a rolling window — with thousands separators (`toLocaleString`). *Listening since* is derived from the earliest `first_ts`, never a hard-coded go-live constant. Three states, one min-height footprint: em-dashes while the roster is in flight, the **fresh-aviary** sentence once loaded-and-empty ("waiting for the first visitor"), the strip otherwise — content swaps inside the same panel so the first bird never shifts the page below (house rule #1). The day count rounds the local-midnight difference (DST skews it by at most an hour) and floors at 1.
  - **Mobile jump chips** (issue #265): below `lg` -- exactly where the rail stops sitting beside the grid and stacks under 40+ life-list tiles -- the masthead tab bar carries right-aligned `events ↓` / `arrivals ↓` anchor chips to `#latest-events` and `#new-arrivals`. Plain hash anchors on purpose (instant, pre-hydration, shareable); passed to `AviaryMasthead` as an optional prop only by the main page (the lamp precedent -- the profile and archive have neither the stacking problem nor the sections). Reordering the mobile stack was considered and declined: the Life List keeps the top spot as the page's identity. (The #265 addendum that aligned a four-tile hero to the page grid + rail was retired with the #418 readout strip — the band is full content width.)
  - **The masthead is station-aware** (#304, epic #212): its sub line renders `mastheadSub(stationName)` (`lib/aviary.ts`, Vitest-covered) — at home, with no name configured, the string is "earl with the ears"; on a station, `MERLE_STATION_NAME` is the whole line so the page says whose yard it is. The old trailing tagline ("every bird the yard has announced") was dropped so the line stays single-row on phone widths. The name is read from env **server-side in the three aviary `page.tsx` files** and passed as an optional prop through `Aviary`/`SpeciesProfile`/`AviaryEvents` into `AviaryMasthead` (the jumps/lamp prop precedent) — a client component reading runtime env would SSR one string and hydrate another; blank and whitespace collapse to home, never a dangling separator.
  - **The masthead navigates** (#357, relabelled and resemanticed by #359): the tab bar is real navigation — `dashboard` (`/aviary`) and `all detections` (`/aviary/events`) — and **the underline marks the current *section*, not the current page: every tab is a live link, the underlined one included** (the GitHub-tabs model). That semantic is the species page's way back: it wears the dashboard underline (a drill-down of the life list, not its own module) while both destinations stay one click away, right where the eye looks for navigation — the alternative was an inert span squatting in that exact spot, with the only exits a corner link nobody reads and the title. Clicking the current page's own tab is a harmless self-navigation, accepted as the convention's cost. Which tab comes from a `tab` prop passed only by the events page (the lamp/jumps prop precedent, not `usePathname`). **There is no way out of the Aviary from its masthead, deliberately** (#361): the old "← control center" corner link is gone, and the `back` prop that once made it read "← the aviary" on the inner pages went with it (#359). The launchpad opens each module in its own window, so a corner link back to the MCC dashboard was a misclick that closed the yard rather than a route anyone was looking for — the masthead's top row now carries the Earl lamp alone, and every remaining move is one *inside* the module. A module whose sub-pages genuinely need a way home should reach for the tab bar, not the corner. The "The Aviary" title is a link home to `/aviary` on every page, resting look unchanged, the house hover the only admission it's a link. Labels live once in `MASTHEAD_TABS` and are **the reader's words, deliberately not the pages' own titles** — the panels still read "The Life List" and "The Full Record" while the bar says what each tab *gets you*; a rename stays a one-line change.
    - **The tabs own a full-width row and the rule rides with them** (#359). The wider tab gap the rename came with is cosmetic; what isn't is that "dashboard" + "all detections" leave no phone-width room beside the #265 jump chips — measured at 375px the nav overflowed its container and the page gained a horizontal scrollbar, and since the labels alone exceed the row the old gap wouldn't have saved it either. So the tabs sit in their own `w-full` span carrying the `border-b`, and the chips wrap beneath it, still right-aligned. The rule moved onto the tab row rather than staying on the `nav` because the alternative — chips pushing the rule to a second line — strands the active tab's underline floating above the rule it is supposed to sit on, and that adjacency *is* the idiom (the one #346's hero tab bar copies). Consequence, accepted: below `lg` the main page's masthead is one chip-row taller; at `lg`+ and on the other two pages (neither passes jumps) it is pixel-identical to before.
  - **The life list is searchable** (#352): a compact input left of the sort pills — the pills' own chrome on an input, an inline magnifier, a ✕ that is always rendered and merely invisible while the box is empty (its seat reserved by the input's padding). `speciesMatches` (`lib/aviary.ts`, Vitest-covered) is a case-insensitive **substring** over the common *and* scientific name — `wood` finds every woodpecker, a Latin fragment works too; deliberately not initials/edit-distance fuzz, because the search's job is "type a fragment of the name you know" and cleverer matching surfaces birds the typist can't see the reason for. The query **filters the rendered order, never re-sorts it** (the archive pills' rule — a control that reshuffles as you use it is house rule #1 broken in a control), and the no-match state holds the grid's reserved footprint with a sentence naming the query. **Session-persisted** (#410) via `sessionStorage` key `aviary.life-list-query` — survives browser Back, the masthead dashboard link, and refresh in the same tab so a multi-species drill-down (type `finch`, open one, go back, open the next) keeps the filter; cleared by ✕ / emptying the box or by closing the tab. Post-mount restore (the clip-gain hydration lesson), not `localStorage`, not a URL `?q=`.
  - **The main page re-grounds itself in the store every minute** (#352, the reconciliation poll): the live bus ticks counts in place but replays nothing after a websocket gap (`audio/events` is an event topic — nothing retained), and the mount-time midnight boundary went stale on a tab left open past it (the code's old "until reload — accepted" posture dated from glance-length sessions; the station kiosk tab is the opposite). Every 60 s — and immediately on `visibilitychange` → visible, exactly when a tab is most stale — the page recomputes its local midnight and refetches `/aviary/roster?today=` (**the existing route; zero new backend**). Everything lands in place: roster entries replace wholesale per species (which also dresses tiles as enrichment lands, and converges the documented ±1 live-tick race), `reconcileOrder` keeps the grid's order exactly and appends the unseen at the end (the live-lifer rule; it never drops a key a payload omitted — a tile must not vanish mid-read), and `reconcileRail` keeps pill order, lands counts in place, appends newcomers, and retires a pill **only on an explicit `today = 0`** — which is how a midnight rollover empties the rail, while a payload merely omitting a just-minted lifer (its row can trail its own bus event) changes nothing: unknown is not zero. The boundary and the counts computed against it move only together on a successful fetch; a failed poll changes nothing at all, stale-but-consistent until the next tick heals it. Both helpers are pure and Vitest-covered. The ticker is deliberately outside the poll — it is already live, and backfilling gap-missed ticker rows is a possible follow-up, not folded in.
  - **Nothing reshuffles on its own** (house rule #1, made structural): the grid's sort order is *state computed only on a sort click* (`rosterOrder()` returns species keys; name/visits × asc/desc, ties always name-ascending) — live count updates land in the tiles in place, lifers append at the end whatever the sort says, and Today's Visitors bumps counts in place and appends newcomers (its pills sized at `text-[11px]` so the longer species names pair two-across the 340 px rail rather than each claiming a row — #207). Every event row reserves a fixed player slot (play / playing / "faded" / no-clip dot — one geometry), empty states reserve their panels' footprint.
  - **Clip playback, raw vs enhanced** (#190): one shared `<audio>` per view (a second click stops the first), keyed throughout on the **raw clip path** — a row is identified by the recording, not by which rendering of it happened to play, so flipping the mode mid-session can't strand a lit button or double-mark a faded one. A `raw`/`enh` switch sits in the Latest Events and Recent Visits label rows, **defaulting to enhanced**; enhanced mode asks for the pass's `-enh` sibling and, on a 404, retries the raw clip and says nothing. That silent retry **is** the existence check — the pass keeps no state about which clips it has processed, so asking for the file is the only honest way to ask whether it exists — and a clip earns the "faded" stamp only once the *raw* file is gone too, which is the one thing that actually means pruned. The route's guard was **not** loosened for any of this: `-` was already in the allowlist, so a sibling is an ordinary clip name by construction (a test asserts the guard still rejects traversal with an `-enh` suffix). One trap, found in the browser and worth keeping: a missing file reports itself **twice**, via the element's `error` event *and* the `play()` rejection, in an engine-dependent order — the first kicks off the raw retry and the second would then land, read the now-current state, and mark faded a clip that was at that moment playing fine. Each attempt therefore owns an `AbortController`: whichever signal arrives first aborts it and acts, the second sees an aborted controller and returns, and listeners registered against the signal detach with their attempt.
    - **Makeup gain** (#189): many real clips are very faint (measured: sighting 107 at rms 0.019) and the element's own volume only attenuates, so the shared element's output routes through a WebAudio graph — `MediaElementSource → GainNode → DynamicsCompressor-as-limiter → destination`. The element stays (streaming, seeking, and the whole #331 fallback ride through the same graph untouched); the graph is built **once, inside `toggle`** — a click handler — because an `AudioContext` born outside a user gesture starts suspended (autoplay policy), and `createMediaElementSource` is a once-only claim on the element. The limiter (−6 dB threshold, 12:1) is the price of offering ×8: a loud clip under full boost soft-lands instead of hard-clipping. The control is a `gain` nameplate beside the `audio` switch (`1× 2× 4× 8×` — steps, not a slider; `coerceGain` in `lib/aviary.ts` snaps any persisted value onto a step, ties toward quieter, Vitest-covered), rendered by all three players via one `AudioControls` cluster whose `flex-wrap` gives the gain steps their own right-aligned line on the 340px rail. The chosen step persists to **one localStorage key for the whole Aviary** (`aviary.clip-gain`) — speakers and ears are one fact across views — and lands post-mount (unity first paint; an initializer read would hydration-mismatch against the server render). Unlike the raw/enh switch, which deliberately changes only what plays *next*, gain applies to the playing clip **immediately** (a 20 ms ramp, not a click): loudness is a session knob, not a per-clip property. No WebAudio (or a claimed element) degrades to the bare element at unity — the knob goes dead, the birds don't. So `read_voice()` tries `voice_section()` and then falls back to `voice_sentences()`.
      - **This is not the paragraph scan #315 rejected, and the difference is the whole design.** Density scored the Wood-Pewee's *plumage*-similarity paragraph at four "vocal" words and would have served it as a sound description. A sentence survives only if it makes a **claim about sound** — a vocal noun as the subject of an assertion (`the song is`, `its calls include`), or a vocal verb *together with* a transcription (`fitz-bew`, `che-bec`) since either alone is far too loose — and any sentence carrying plumage vocabulary is **vetoed outright**. That veto is what separates the two approaches. A **two-sentence floor** keeps it quiet on thin articles, which is most of what it is pointed at.
      - **Precedence is absolute and deliberately not a length comparison.** A dedicated section always wins, even where the fallback would return more words: the Carolina Wren measures 2,308 characters of section against 1,069 the sentence reader would assemble, and the section is the better read every time — the article's own account of the bird rather than lines gathered from wherever they fell. Measured before it shipped and again against the shipped code: **recall 3/3, precision 7/7** (silent on every article that genuinely says nothing), **no-harm 4/4**.
      - **`voice_source` is rendered, not just recorded** — `voiceCredit()` in `lib/aviary.ts` (Vitest-covered) stamps a gathered entry "gathered from the article · via Wikipedia" so assembled sentences are never mistaken for an encyclopedia's considered paragraph. Same licence either way; what differs is the claim being made about the text. An unknown or missing source reads as the section case, since pre-#317 rows are all sections by construction.
      - **`voice_version` is what makes the improvement actually land.** The backfill arm now keys on `COALESCE(voice_version, 0) < VOICE_VERSION` instead of #315's `voice_checked_ts IS NULL` — that test could only ever fire once, so after #315 ran, every row had a stamp and the new reader would never have been called on a deployed box without a hand `--refresh-all`. Keying on the generation keeps the same termination guarantee (one pass lifts every row and the arm empties) while making the next improvement a one-line bump rather than a migration. `voice_checked_ts` survives purely as "when did we last look". **Bumping `VOICE_VERSION` without updating the seeded rows in `test_listener_enrichment_loop.py` puts those tests back on the worklist and makes them fetch live Wikipedia in CI** — they read the constant for exactly this reason.
    - **Only a real heading counts for the section reader, and that is a measured decision.** Across 30 yard species, 22 have a section whose heading names a sound (`Vocalization`/`Vocalizations`/`Vocals`/`Voice`/`Song`/`Songs`/`Song and calls`/`Call and flight`), at top level and nested alike — the match is **word-bounded**, because an unanchored `cri` matches inside "Des*cri*ption" and an unanchored `vocali[sz]ation` misses the Common Grackle's bare `Vocals`. Scanning loose paragraphs to recover the other 8 was tried and **rejected**: it returns the Eastern Bluebird's "In culture" paragraph about "Over the Rainbow" and the cowbird's brood-parasitism neurology. On a panel whose whole job is helping someone judge a false positive, confidently wrong prose is worse than an honest blank — so no section means `NULL`, no panel, and **no empty state either** (reserving a footprint for something that is never coming is not house rule #1, it is just a permanent hole).
    - **`voice_checked_ts` is stamped whether or not a section was found**, and it was #315's termination guarantee: without it the ~27% with no section would have sat on the worklist and been re-asked forever — `species_analysis`'s `checked_ts`-vs-`generated_ts` split, for the same reason. Since #317 the arm keys on `voice_version` instead (see above) and this column survives purely as "when did we last look", for humans.

Unclamped on a phone, the Carolina Wren's section alone runs 965 px and buries the chart and the field desk under it — the burial #196 already litigated; on a laptop there is room for the whole thing, and spending it on a control instead of on prose is the worse trade. The `read more` control then disappears for free, because an unclamped block measures `scrollHeight === clientHeight`; `md:hidden` on the button is the belt to those braces. The DDL rides both writer routes in-transaction (the negatives precedent) *and* sightings' `connect()`, so deploy order can't strand a rule. **The overlay** opens from a quiet `detection` stamp beside `remove species` — new chrome at the `text-xs` floor in `text-inkdim`, deliberately not the legacy 10px remove size, with touch-sized confirm/cancel — and follows the #216 dialog pattern (`fixed` on the viewport, mounted outside every `.panel`, Escape/backdrop cancel, reserved error line). Three things in one dialog: **confidence** as steps, Default / 0.80 / 0.90 (the clip-gain idiom; Default = no row / `threshold` NULL; the steps go quiet while ignore is checked — an ignored bird's floor is moot, exactly as the gate treats it); **ignore from now on** (`exclude` — future detections never publish; the copy says out loud that history stays, deletion remains Remove); **allow even if the map says no** (`always_include` — still owes threshold + confirm + speech). An all-defaults save **deletes the row** rather than storing a no-op: "cleared" and "never ruled" are the same state (`ruleIsEmpty`), so the listener's map stays exactly as big as the operator's opinions. **The active rule is a reserved stamp in the hero meta** — a fifth `dl` entry reading `default` / `threshold 0.80` / `ignored` / `map override` (`ruleStamp`, exclude speaking alone since it makes the other fields moot), rendered in every state so a rule landing can never pop in and shift the page (house rule #1). The rule rides the roster payload (`rule` on each entry) via a **separate tiny query merged in code — deliberately not another rung on the LEFT JOIN cascade**; a pre-#506 store answers with none and every stamp reads default. There is no always-include UI except on a species already on the life list (the overlay lives on its page) — fine for v1. Pure helpers (`ruleStamp`, `parseRulePayload`, `ruleIsEmpty`, `speciesRuleFrom`, `coerceRuleThreshold` — snaps a hand-edited stored value onto the steps, ties toward the lower bar — and `removalUrl`) live in `lib/aviary.ts`, Vitest-covered.
